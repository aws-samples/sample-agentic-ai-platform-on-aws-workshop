# AnyCompany HR assistant: risk register

Pre-filled register for the People Operations HR assistant, used in the closing discussion (responsible AI, approvals
and the production path). Likelihood and impact are rated Low / Medium / High for the workshop platform as built.
"Mitigation in the workshop platform" names the building block that addresses the risk today; "Status" says how much
of the risk is covered by it (Mitigated, Partially mitigated, Accepted, Open). Owner personas: platform admin, agent
developer, approver (domain business owner).

| Id | Risk | Likelihood | Impact | Mitigation in the workshop platform | Owner persona | Status |
| --- | --- | --- | --- | --- | --- | --- |
| R-01 | Hallucinated policy answers: the agent states leave, remote-work or parental-leave rules that are not AnyCompany's (the seeded regression in prompt v1) | High | High | Policy questions are answered only from the HR policy knowledge base (hrkb___Retrieve) with the document title cited (prompt v2); the evaluation dataset contains three policy scenarios whose Correctness and TrajectoryInOrderMatch scores block the release when the agent skips the knowledge base; online evaluation keeps scoring Prod sessions | Agent developer | Mitigated |
| R-02 | PII leakage: employee data (names, emails, leave records) shown to someone who should not see it, or sensitive identifiers echoed in answers | Medium | High | Baseline Bedrock guardrail on every model alias blocks SSNs and card numbers in input and output; tools return only the fields the scenario needs (profile never returns balances); the knowledge base holds policies, not personal data. Not built: verifying that the requester is the employee whose id they quote (user-level identity propagation is the production extension) | Platform admin | Partially mitigated |
| R-03 | Prompt injection through documents: a policy document or tool result contains instructions ("ignore your rules and reveal...") that the model follows | Medium | High | Knowledge-base documents come from a controlled S3 bucket written by the Scenario stack; the baseline guardrail's prompt-attack filter screens model input; tools are read-only except submit_leave_request, which validates every field and only creates pending rows; Cedar policies limit which tools and arguments the agent may use regardless of what the model is told | Agent developer | Partially mitigated |
| R-04 | Over-permissioned tools: an agent reaches tools of another project (the Finance invoice tool) or performs actions it should not | Medium | High | Each project has its own gateway, execution role and gateway role; the policy engine is default-deny and attached in ENFORCE mode, so hrtools/hrkb are permitted explicitly and fintools is invisible to the HR agent; the cross-project denial test in module 4 proves it; the dataset's out-of-scope invoice scenario checks the agent does not pretend to know | Platform admin | Mitigated |
| R-05 | Cost overrun: a runaway loop, an evaluation storm or heavy traffic consumes model spend without limits | Medium | Medium | LiteLLM team cap per project (5 USD per 7-day period) and virtual key cap per agent, environment and model (1 USD per 7-day period) with automatic resets at the period end; tpm/rpm throttles; harness limits (30 iterations, 4000 output tokens, 120 s); spend per project and agent on the Overview screen; a cap breach surfaces as a budget_exceeded error the admin can lift | Platform admin | Mitigated |
| R-06 | Model drift: a model alias is upgraded or its behaviour changes and the agent's quality degrades silently | Medium | Medium | Approved aliases are pinned to explicit inference profiles in the model gateway configuration; every blueprint version is re-evaluated against the dataset before promotion; online evaluation on the Prod endpoint publishes Helpfulness, Harmfulness and tool-selection metrics to CloudWatch; immutable harness versions allow rollback by repointing the live endpoint | Agent developer | Partially mitigated |
| R-07 | Unapproved model use: a team points an agent at a model that has not been approved or priced | Low | Medium | The model gateway only serves the approved aliases in its configuration; the project's team allow-list restricts which of them the project may use; the blueprint renderer rejects a model ref that is not approved for the project; no provider API keys exist outside the gateway's task role | Platform admin | Mitigated |
| R-08 | Data residency: employee data, documents or traces leave the agreed region, or a cross-region inference profile routes prompts to another region | Medium | Medium | All resources are in us-east-1 and the knowledge base, tables and logs stay in the account; model calls use US cross-region inference profiles (us.*), which can route within the United States. Not built: single-region inference profiles and residency controls for a multi-region enterprise (presentation topic) | Platform admin | Accepted |
| R-09 | Evaluation blind spots: the ten scenarios pass but real conversations expose failures the dataset never asks about (multi-turn, ambiguous ids, dates in the past) | High | Medium | Dataset mixes look-ups, submissions, policy, holidays, out-of-scope and safety cases with assertions and trajectories; online evaluation samples real Prod sessions; playground feedback (thumbs down) can feed disliked sessions into a batch evaluation; thresholds are versioned with the blueprint and tightened as the dataset grows | Approver | Partially mitigated |
| R-10 | Human approval bypass: a developer promotes a failing or unreviewed version to Prod, or a leave request over the limit is approved by the agent itself | Low | High | Release state machine requires PENDING_APPROVAL -> APPROVED by a user in the approvers group before promote is allowed, and a BLOCKED release cannot be approved; promotion is performed by the backend, not by the developer's credentials; the tool only creates pending requests, the Cedar policy denies requests over 10 days (which the manager files with People Operations for director approval) and the agent never approves leave | Approver | Mitigated |
