The run-through

This is a complete run-through from a fresh AWS account to the cleaned-up one. A facilitator uses it to rehearse what an attendee experiences through the workshop.
The document outlines short steps, exact commands, where to look in the UI. The detailed explanations live in the course pages: docs/v2/course (the path, the agenda, Get started, one page per module, clean up).

Part 0: get the code5 min

  1. Clone the repository (the learners do the same in Get started, step 1). repo.zip from scripts/package_for_workshop_studio.py is the deployer's CodeBuild source, not an attendee download. 
    git clone <repository URL> && cd workshop-agentic-ai-platform   # frontend/dist is git-ignored: Part 2 builds it
  2. Open the course once: v2/course/index.html (the path, the agenda, Get started) and workshop-guide.html (architecture, services). Keep Get started open: its six steps are what every learner does before module 1.

Part 1: laptop and account10 min

  1. Check the laptop tools. No Docker anywhere; no AWS CLI for learners.
    Tool Version Check
    Python 3.12 or later No laptop install needed: uv sync installs 3.13 from .python-version. Check after sync: uv run python --version
    uv 0.12.10 or later uv --version; install: curl -LsSf https://astral.sh/uv/install.sh | sh
    Node.js 20 or later node --version; every learner needs it: workshop apply 1 runs the pinned CDK CLI from npm install
    AWS CLI v2 2.36 or later aws --version; facilitators' own accounts only. Learners paste the event credentials and never call aws
    Git; VS Code or any editor git --version; an editor with YAML highlighting for design-record.yaml (code design-record.yaml)
  2. Account: administrator access, region us-east-1. Own account: use a profile that refreshes itself (for example an isengardcli credential_process profile). Event account: the event page issues fresh credentials at any time; when they expire, paste the fresh lines, set the region, run workshop status again and re-run the interrupted workshop apply N.
  3. Export the profile and region, verify the account: 
    export AWS_PROFILE=<profile> AWS_DEFAULT_REGION=us-east-1
aws sts get-caller-identity   # the account id must be the workshop account
  4. Bedrock model access: do nothing yet. The model gateway exists only after workshop apply 1, which runs the doctor at its end (the all-seven scripts/deploy.sh runs it after the deploy). If the doctor's LiteLLM chat completion row fails with an access error, submit the one-time Anthropic use-case form under Model access in the Bedrock console and run uv run python scripts/doctor.py again.

Part 2: deploy the control plane before the dayabout 12 min

What Workshop Studio does in every attendee account before the event; in your own account, do it yourself. It deploys AgentPlatform-Web, -Auth, -Platform (the control plane: web UI, API, state, worker, the Cognito user pool and app client) and AgentPlatform-Scenario (the sample data). The landing zone is the learners' module 1, the personas and Keycloak their module 2.

  1. Python environment with the workshop command and the pinned CDK CLI, 2-5 min: 
    uv sync && npm install
source .venv/bin/activate   # Windows: .venv\Scripts\Activate.ps1; or prefix every command with uv run
  2. Deploy the four pre-day stacks, about 12 min. The script rebuilds frontend/dist when it is missing or older than the sources (the Web stack ships whatever it holds), bundles the backend, deploys with --concurrency 4, retries once with concurrency 1 on a network error and ends with the doctor. 
    (cd foundation && npx cdk bootstrap)   # once per account and region; workshop deploy does it itself when CDKToolkit is missing
scripts/deploy.sh --pre-day             # Web, Auth, Platform, Scenario; or: workshop deploy pre-day (builds the UI when missing)
    The seven-stack scripts/deploy.sh (about 16 min, also creates the personas) is the self-paced path: workshop apply 1 then finds its stacks deployed and goes straight to its checks. workshop apply 2 finds the personas but still deploys AgentPlatform-Idp (about 7 min) unless scripts/deploy.sh --idp ran as well.
  3. Read the doctor. The landing-zone rows read not deployed and the personas not created: expected before modules 1 and 2, and the doctor does not fail on it. Passwords exist only after workshop apply 2. 
    uv run python scripts/doctor.py   # --show-passwords works after workshop apply 2
  4. Check the stacks the way the learners will in Get started, step 5: 
    workshop status
# account stacks in us-east-1:
# AgentPlatform-Network         not deployed      landing zone
# AgentPlatform-SharedServices  not deployed      landing zone
# AgentPlatform-ModelGateway    not deployed      landing zone
# AgentPlatform-Web             CREATE_COMPLETE   control plane
# AgentPlatform-Auth            CREATE_COMPLETE   control plane
# AgentPlatform-Platform        CREATE_COMPLETE   control plane
# AgentPlatform-Scenario        CREATE_COMPLETE   sample data
# AgentPlatform-Idp             not deployed      corporate IdP (module 2)
    Eight rows: four CREATE_COMPLETE, four not deployed. The first look at the UI waits for module 2: the personas exist only after workshop apply 2.
  5. Alternative: deploy through the Workshop Studio deployer template (what the event does; DeployScope pre-day about 12 min, all about 20 min) 
    # build/workshop-studio/repo.zip + deployer.yaml; --skip-ui-check lets CodeBuild build the UI
uv run python scripts/package_for_workshop_studio.py
aws s3 mb s3://<bucket> && aws s3 cp build/workshop-studio/repo.zip s3://<bucket>/ws/repo.zip
aws cloudformation deploy --stack-name agent-platform-deployer --template-file workshop-studio/deployer.yaml \
  --capabilities CAPABILITY_IAM --parameter-overrides AssetsBucketName=<bucket> AssetsBucketPrefix=ws/
# DeployScope defaults to pre-day (Web, Auth, Platform, Scenario); DeployScope=all deploys the seven stacks
# outputs: UiUrl, ApiUrl, ModelGatewayUrl, UsersSecretArn, PersonaPasswordsCommand, DoctorStatus, DeployerBuildId, DeployerBuildLogs
aws cloudformation describe-stacks --stack-name agent-platform-deployer --query 'Stacks[0].Outputs'

    Build logs: CloudWatch log group /aws/codebuild/agent-platform-deployer-deployer. ModelGatewayUrl reads "not deployed yet" until module 1; PersonaPasswordsCommand prints the passwords after module 2. Deleting the stack starts a destroy build (destroy path not yet exercised end to end).

  2. Remove what modules 3-7 built, in reverse order: about 10 min, mostly AgentCore deleting harnesses and memories in the background (2-8 min). Troubleshooting

Symptom Action
command not found: workshop, The term 'workshop' is not recognized The terminal has not activated .venv, or uv sync has not run: source .venv/bin/activate or .venv\Scripts\Activate.ps1; or prefix the command with uv run. PowerShell running scripts is disabled on this system: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once, then activate again.
cannot read the platform configuration from SSM (…) Wrong account or region, or the control plane is not deployed: the first line of workshop status must read us-east-1; unset or change AWS_REGION and AWS_DEFAULT_REGION; own account: workshop deploy pre-day first. Learners have no AWS CLI: do not send them to aws sts.
ExpiredToken, no usable AWS credentials, … SSM (NoCredentialsError …) Paste fresh lines from the event page, set the region, run workshop status again; re-run the interrupted workshop apply N (idempotent).
Node.js 20 or later is needed for cdk deploy, the pinned CDK CLI is not installed Module 1's deployment runs the CDK CLI: install Node.js 20 or later, then npm install at the repository root.
certificate verify failed, self-signed certificate, ETIMEDOUT during clone, uv sync or npm install A company proxy or TLS inspection: set HTTPS_PROXY (PowerShell $env:HTTPS_PROXY); uv: UV_NATIVE_TLS=1; npm: npm config set proxy <url>; or the guest Wi-Fi.
workshop apply 1 or scripts/deploy.sh: @smithy/node-http-handler ... did not establish a connection ... 10000 ms, Failed to publish asset Laptop network, VPN or proxy: the CDK CLI could not open S3 connections while uploading the 19 MB backend bundle. Finished stacks are kept. Learners: run workshop apply 1 again. Pre-day: scripts/deploy.sh --pre-day resumes and retries once with --concurrency 1 --no-asset-parallelism; or start with DEPLOY_CONCURRENCY=1 scripts/deploy.sh --pre-day. Check the VPN or HTTPS_PROXY if it persists.
workshop apply 1: the gateway "did not answer yet" The ECS Express service needs a minute after the stack completes: workshop apply 1 --no-deploy repeats the checks and the doctor without redeploying.
AuthError: Cognito refused the sign-in; Switch persona fails with 502 SIGN_IN_FAILED Re-run workshop apply 2: it re-applies the stored passwords (permanent). Facilitator fallback: aws cognito-idp admin-set-user-password --user-pool-id $(aws ssm get-parameter --name /agent-platform/auth/user-pool-id --query Parameter.Value --output text) --username <admin | developer | approver> --password '<from the agent-platform/users secret>' --permanent.
workshop obo step 1 fails with a sign-in error (modules 4, 6) The Keycloak task restarted since workshop apply 2 and the employee is gone with it: run workshop apply 2 again (about a minute).
workshop apply 3: WARN could not inspect the agent role ... IAM may still be propagating The new role was not visible yet: run workshop apply 3 again; it is safe to repeat.
workshop call --as finance-dev ... → HTTP 403 Expected: IAM denies Finance's role on HR's gateway before any policy runs. workshop call --as assumes the project's agent role.
MCP call denied, JSON-RPC error -32002 Expected for workshop call --as hr-dev submit_leave_request E1001 15 after Set ENFORCE: the max_leave_days forbid rule blocks before the tool runs. Elsewhere: the gateway is in ENFORCE and no policy permits that tool for that role.
Overview Allow / Deny still 0 after the LOG_ONLY call CloudWatch is late: up to four minutes. workshop apply 7 waits up to three minutes for the Prod metrics for the same reason.
Playground "Spending cap reached"; BUDGET_EXCEEDED, HTTP 422 Expected after workshop cap --dev low in module 5 (if that call still passes, the proxy writes spend every 10 s: run it once more). Fix: workshop cap --dev restore (or workshop cap --dev <USD>), or Platform admin on the Keys tab. Module 6 starts with the cap restored; the record's cap is 1 USD/7d.
Release REJECTED in the UI Terminal by design. Re-run workshop apply 6: it ignores REJECTED releases and creates a new one.
Release EVALUATING (created on the Releases screen or with Run evaluation) The platform worker runs it and workshop apply 6 follows that run. Still EVALUATING after 15 minutes: open the Releases screen, Run again appears once the job has stalled, then run the command again.
workshop apply 7: no Prod agent yet Approve and promote release 2 first (module 6, as Domain approver).
